# What the analyzer does not check

The analyzer stays quiet where it cannot see a quantity. The cases below produce no diagnostic. They are the usual
reasons a mistake gets through.

## Unknown results

- Methods with plain `float` parameters and return types. Calling them is fine, but the result has no quantity.
- `Math.Sqrt`, `Math.Pow`, `Math.Cbrt`, and every other `Math` or `MathF` method outside the
  [quantity-preserving list](how-it-works.md#how-quantities-combine). `Math.Sqrt(area)` is not a length.
- A conditional with mismatched branches. `flag ? length : time` is unknown, so `Metre m = flag ? length : time;`
  passes. Passed to a `Metre` parameter, it is reported as an unannotated argument.
- The `%` operator, bitwise operators, shifts, `++`, and `--`. The one exception is `&` on vectors, which keeps the
  quantity of the operand that is not a mask.
- `var` locals initialized from unknown values.

## Vector code

- Vector helper methods outside the [helper table](how-it-works.md#vector-helper-methods). That covers
  `Vector.SquareRoot`, bit casts such as `AsVectorSingle` and `As<T, U>`, `BitwiseOr`, `Xor`, and shifts.
- Hardware intrinsics such as `Avx.Add`, `Sse.Multiply`, `AdvSimd.Add`, and `Fma.MultiplyAdd`.
- Masks. Comparison results have no quantity, so a mask turned back into a value, as in `AsVectorSingle(mask) * x`,
  is unknown.
- Generic helpers. `Load<T>(T[] values, int i) => new Vector<T>(values, i)` returns an unknown vector, because `T` is
  `float` at the call site. Load with `new Vector<float>(values, i)` directly, or write one helper per quantity.
- Spans made with `AsSpan` or a slice. `new Vector<float>(values, i)` keeps the element quantity, but
  `new Vector<float>(values.AsSpan(i))` does not. Scalar code has the same limit for `values.AsSpan()[0]`.
- `MemoryMarshal.Cast` assigned to a local. That is a whole-collection assignment, so the local needs its own
  declared type, such as `Span<Vector<Pascal>>`.
- Components of `Vector2`, `Vector3`, and `Vector4`. `.X` has no quantity.
- Lanes that hold different quantities, such as an interleaved `xyzw` layout. A vector has one lane quantity.

## Constructs without a quantity

- Tuples, deconstruction, and `foreach` variables, even when the written type is an alias.
- Switch expressions. `d switch { > 0f => d, _ => t }` is unknown, so the analyzer does not compare its arms.
- Pattern variables from `is`. After `if (x is Metre m)`, `m` has no quantity.
- Whole arrays and collections. Only elements carry a quantity. `Metre[] xs = pascals;` passes, and so does a
  `Pascal[]` passed to a `Metre[]` parameter.
- `params` arguments. A `params Metre[]` parameter is an array, so the analyzer does not check the values passed to it.
- `yield return` values. The analyzer does not compare them with the iterator's element type.
- Lambdas without a declared return quantity. `() => pressure` assigned to a `Func<Kelvin>` passes.
- String concatenation. `"p=" + pressure + " T=" + temperature` is not a sum.

## Quantities that are not inherited

- An interface member. `[Quantity]` on an interface property does not apply to the implementing property. Code that
  uses the class sees no quantity. Code that uses the interface does.
- An override. A member that overrides a `Kelvin` method does not inherit the alias, so declare it again.

## Code the analyzer skips

- Generated code. Roslyn treats `*.g.cs` files and files marked `<auto-generated/>` as generated.
- Code in other assemblies, unless its declarations carry `[Quantity]` or `[ElementQuantity]`.

## Not in the model

- Fractional exponents. Exponents are integers, so a catalog cannot declare $L^{1/2}$.
- Two meanings for one dimension. See [Gotchas](gotchas.md#same-dimension-different-meaning).
